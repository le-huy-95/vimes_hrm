Design §3 — Flows, errors, tests

Core ghi DB → outbox → google-sync push/pull · Flutter gọi API có sẵn + PATCH mới

Data flow
  1. Flutter PATCH due / assign / claim → core-service
  2. Core cập nhật tasks / task_assignees, bump version, ghi task_events
  3. Với mỗi ACTIVE assignee có Google link sẵn sàng → notifyGoogleTaskPush (title, notes, status, due)
  4. google-sync-service TASKS_PUSH partial patch; TASKS_PULL merge due vào task (creator/local-wins)
Errors (giữ mã hiện có + mới)
  • CLAIM_DISABLED / CLAIM_FULL / ASSIGN_FULL / NOT_ASSIGNEE — giữ
  • INVALID_DUE_DATE — format không phải YYYY-MM-DD
  • NOT_GROUP_MEMBER — gán user ngoài nhóm
  • Google AUTH_REQUIRED — app vẫn đổi due/assignee; sync dừng (đã có)
Tests tối thiểu
  • BE: PATCH due → payload push có due; pull Google due cập nhật DB khi local cũ hơn
  • BE: create không assignee → không enqueue push; claim/assign → có push
  • FE: bloc/event due + assign member picker (smoke / unit nhẹ nếu đã có pattern)
Out of scope đợt này
  • Subtasks, star, Drive attach, multi tasklist, start/end time, unassign API, Google-like detail sheet
